# Project workspaces with contx

Use the machine interface (`--json`) for agent actions. Success is one JSON object on stdout; failure is a nonzero exit with a JSON error on the last stderr line (earlier lines can be Git progress). Read `contx --help` for current syntax. A **candidate** is a directory discovered from contx config; only candidates can be opened or deleted. `open` focuses/creates a multiplexer target, **not** a shell `cd` or a transfer of a running agent.

1. **Select:** Run `contx --json list`; pick a `candidates[].path` by its actual path, not its label. Confirm the project and branch with Git before making changes. If the directory already exists but isn't listed, configure its parent in contx; clone only when the repo is absent. Clone to an intended, new path using `contx --json clone --add-parent <source> <destination>`. Check `discoverable` in the result and list again. `--add-parent` explicitly records an uncovered parent in config; omit it if config should remain unchanged. A clone never opens a workspace.
2. **Isolate branch work if needed:** From a *repository-root candidate*, run `contx --json worktree create --new-branch --add-parent <repo> <new-branch> <new-destination>`; omit `--new-branch` only when checking out an existing local branch. A new branch starts at the selected repo's HEAD. Confirm both paths and branch first. Destination must be absent; the new checkout is separate from the primary checkout. Check `discoverable`, then list again. Git failure can leave a partial directory: inspect it before retrying.
3. **Open the intended target:** Inside Herdr, run `contx --json --multiplexer herdr open <candidate-path>` (or `--multiplexer tmux` in tmux). For Herdr, save the returned `workspace_id`. If several matching workspaces exist, contx fails with JSON `workspace_ids`; choose one deliberately and retry with `open --workspace-id <id> <candidate-path>`. The ID must still match the path. A Herdr session, controller workspace, and project workspace are distinct: create subsequent tabs/agents in the **returned** project workspace (`herdr tab create --workspace <workspace_id> --cwd <candidate-path>`, or the subagent launcher’s workspace option), not in the controller. Opening a workspace does not move this agent or change its cwd; choose an explicit cwd when running project commands.
4. **Delete only after inspection and approval:** Run `contx --json delete --dry-run <candidate-path>` and examine `preflight.target.path`, `class`, `strategy`, **every** `warning` and `blocker`. Get explicit approval for the selected path and strategy; then, if still appropriate, run `contx --json delete --force <candidate-path>`. `--force` accepts warnings but cannot bypass blockers; JSON mode never prompts. `--permanent` is an irreversible strategy for symlinks, ordinary directories, and standalone repositories; use it only with specific approval (and check `permanent-delete` config, which can already select it). Linked worktree deletion is non-force Git worktree deletion. An active pane or process inside the target blocks deletion: move the work to a safe workspace first. Recheck if state changed since dry-run.

For unattended Git/SSH, use preconfigured credentials. A failed clone/worktree/config update leaves surviving directories intact; inspect the error and filesystem before any retry. `contx` manages candidates and activation; for pane/tab lifecycle use the multiplexer’s own interface, scoped to the returned target ID.
